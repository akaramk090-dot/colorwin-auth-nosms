# Lottery bet history and settlement notifications

The imported K3, 5D and TRX game screens use `dist/source-home/lottery-history.js` and `.css` for their My history panel and settlement popup. Betting controls, game/chart screens and wallet payout calculations retain the existing source implementation.

`bridge.js` now supplies string game/selection types expected by the original components, infers the lane from a result-query period when no typeId is provided, and forwards unit amount plus quantity for new batches. The UI reads only authenticated server snapshots. Pending orders settle to win/loss once, with a five-second dismissible result popup; historical settled rows are not replayed as new notifications.

Database migration order: `supabase/lottery-order-history.sql` adds batch linkage, quantity metadata and complete batch snapshots to the existing RPCs. It recovers existing order groups through deterministic child request IDs. This file includes quantity_known for fresh setup. The incremental live upgrade `supabase/lottery-history-quantity-known.sql` was applied separately on the existing deployment; do not apply it again after a fresh setup that already contains that column. Legacy quantities were never saved and display a dash. All new batch requests validate unit_amount * quantity = per-selection stake. Existing payout formulas and access grants are preserved.

Each summary shows the amount returned on a winning order, while the Details Win/loss row shows net payout minus purchase amount. The 2% after-tax breakdown is informational and is not a second wallet debit. Raw per-selection records remain available for audit; groups are displayed as one order. Up to 100 recent lines select orders, and all members of those orders are returned so a multi-bet cannot be partially displayed.

Validation: `node reference-home/check-lottery-order-history.cjs` mocks all RPCs and tests all three original screens, grouping, details, quantity forwarding, wins, losses, manual and automatic close. `tests/lottery-order-history.sql` uses temporary test identities in a rolled-back transaction to verify real RPC metadata, idempotency, cross-user isolation, validation, settlement and wallet balances. It does not place bets for real users.

Round notification rule: group all orders by game, lane and round before notifying. Wait until every included line settles, then show exactly one Win popup when total payout is positive; show Lose only when all lines return zero. Popup winnings show the total returned by the winning lines. The popup uses WinGo's 100-particle left/right wing trajectories and timing. K3 history and popup reuse the existing n1–n6 dice assets; the large main result keeps its original 3D num1–num6 artwork. Single-number badges use odd/green and even/red; TRX 0/5 use equal violet splits.

WinGo HTTP fix: UUID v4 request IDs use crypto.getRandomValues when crypto.randomUUID is unavailable on a LAN HTTP page. Interrupted retries retain the original request ID. Browser check `reference-home/check-wingo-http-bet.cjs` uses mocked wallet responses and verifies one debit on retry. `tests/wingo-bet-retry.sql` verifies the real RPC with temporary test users inside a rollback. `reference-home/check-lottery-round-results.cjs` covers partial settlement, mixed results, all-loss periods, one notification per period, dice assets and badge colors for K3/5D/TRX.
